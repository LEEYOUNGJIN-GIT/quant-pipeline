# quant-pipeline

Heterogeneous-agent quantitative research pipeline for a KRW-based portfolio of KRX and NYSE assets. The specification is
`IMPLEMENTATION_SPEC.md`; `PROGRESS.md` is the build log; `open-questions.md` lists every point the spec leaves open and how it was
resolved.

## What is here, and what it proves

| Lane | Data | Status |
|---|---|---|
| Fixture (`configs/fixture_3asset.yaml`) | bundled, deterministic 3-asset fixture | complete, verified in CI on every push |
| Research, **synthetic** (`configs/research_8_12asset.yaml`, reduced by `tests/support/research_smoke.py`) | generated data, labelled `synthetic_engineering_test` | runs end to end, resumable, look-ahead tested, holdout procedure tested |
| Research, **real data** | a verified, content-addressed snapshot collected from licensed providers | **not run yet**: no snapshot has been collected |

Synthetic runs show that the machinery works. They say nothing about strategy performance, and the code refuses a synthetic snapshot
unless you pass `--allow-synthetic`.

## Install

```bash
uv sync --frozen --extra dev          # exact versions from uv.lock (CPython 3.12.15 in CI)
uv sync --frozen --extra dev --extra research-online   # adds yfinance for the optional collector
```

## Fixture lane

```bash
uv run quant-pipeline doctor --config configs/fixture_3asset_aux1024.yaml
uv run quant-pipeline plan   --config configs/fixture_3asset_aux1024.yaml --run-id demo
uv run quant-pipeline run    --config configs/fixture_3asset_aux1024.yaml --run-id demo
```

Outputs go to `outputs/runs/<run-id>/` (checkpoints, `report.md`, `report.html`).

## Research lane

```bash
# 1. A snapshot must resolve to data/snapshots/research/<snapshot_id>/ (the `current` pointer is only a convenience).
uv run quant-pipeline data validate --config configs/research_8_12asset.yaml

# 2. Run (resumable: re-running the same run id continues from the last valid checkpoint).
uv run python -m quant_pipeline.research_pipeline --run-id r1 --out-root outputs/runs \
    --config configs/research_8_12asset.yaml [--stop-after N] [--allow-synthetic]
```

The run stops after the pre-holdout report. The final holdout stays sealed until it is opened on purpose:

```bash
QUANT_FINAL_HOLDOUT_ACK=I_UNDERSTAND_THIS_OPENS_THE_FINAL_HOLDOUT \
  uv run quant-pipeline holdout open --config configs/research_8_12asset.yaml --run-id r1 --unlock-final-holdout
```

Opening is allowed once per lineage, needs the frozen selection and a valid pre-holdout state, writes an audit record and proves the
pre-holdout artifacts unchanged. A second attempt is refused.

## Data collection (optional step, not run in this repository's CI)

`quant-pipeline data fetch` materializes an immutable snapshot from a provider adapter. The repository is public and provider data is
generally not redistributable, so `data/snapshots/`, `data/cache/` and `outputs/runs/` are git-ignored. Do not commit them; do not print raw data in
logs.

## Verification

```bash
uv run ruff check src tests tools
uv run python tools/verify.py --run-id local --allow-known-gaps    # full test suite and the check registry
```

`tools/verify.py` without `--allow-known-gaps` fails by design while a check is partial. `tests/known_gaps.json` pins exactly which ones
(currently INV-DATA-001: no real-data research run exists, and INV-BLACKBOX-001: the regression snapshot is generated by this
implementation). Local runs on CPython other than the locked 3.12.15, or as root, show a few environment-only failures that pass in CI.

## Layout

- `src/quant_pipeline/` library and CLI; `configs/` profiles; `data/fixtures/` the bundled fixture
- `tests/` unit, integration, golden, black-box; `tests/check_registry.py` maps every spec check to its evidence
- `tools/` verification and fixture-generation scripts
